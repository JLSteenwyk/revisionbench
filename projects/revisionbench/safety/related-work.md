# Closest methods and contribution boundaries

Reviewed September 13, 2026. Exact inspected implementation revisions and file hashes are in [literature-sources.json](literature-sources.json). This is a focused methods review, not an exhaustive novelty search.

[AgentDojo's task interfaces](https://github.com/ethz-spylab/agentdojo/blob/089ed468cf3ed0322acc66b0211f26d9d90dbf60/src/agentdojo/base_tasks.py) separate user-task utility from attacker-goal evaluation, using final environment state and optional tool traces. This is direct precedent for programmatic task/security checks and for using traces when final state misses behavior. Its `security` method in this interface returns whether the injection goal occurred; names alone must not be assumed to mean a safety pass. RevisionBench should not claim that separate safety and utility scoring is novel.

[tau-bench's environment evaluator](https://github.com/sierra-research/tau-bench/blob/59a200c6d575d595120f1cb70fea53cef0632f6b/tau_bench/envs/base.py) compares the resulting database hash with a state produced by reference actions and separately checks specified response content. This supports using independent expected states. Final-state agreement alone does not establish that all intermediate operations were permitted. Our proposed event-based authorization and report-versus-receipt checks address that measurement distinction in scientific-file tasks; that distinction is not a priority claim.

[ToolEmu's evaluators](https://github.com/ryoungj/ToolEmu/blob/ac4a7ab7ed8c7985d96231e214bd6b54304b7ddb/toolemu/evaluators.py) use prompt-based trajectory evaluation for risky tool calls and helpfulness. Its [framework](https://github.com/ryoungj/ToolEmu) emulates tool environments to explore risks. RevisionBench's planned deterministic scorer covers a smaller, explicitly specified set of facts supported by local execution and structured reports. It does not replace open-ended risk assessment or inherit ToolEmu's coverage.

[AgentSpec](https://arxiv.org/abs/2503.18666) specifies runtime constraints through rules and enforcement. The inspected [enforcement implementation](https://github.com/haoyuwang99/AgentSpec/blob/e6fa3902e2cfb9681f454b355691b771f70543f8/src/enforcement.py) distinguishes continuing, skipping, stopping and reflection. Runtime denial is therefore an enforcement result, not by itself evidence that the underlying model refrained from requesting the action. Our scorer must retain the request before recording enforcement. Configurable policy enforcement is established work.

The candidate contribution is the combination of controlled scientific corrections, permission-inverted tasks, independent numerical outputs, and structured report verification with explicit observation gaps. Each component has precedents. The present evidence does not establish that this combination is novel, impactful enough for publication, or superior to existing benchmarks. Further review and empirical construct validation would be needed before making those claims.
